# Events Service

MVP на Spring Boot 3.5.16 и Java 21. Сервис публикует события в Kafka и сам обрабатывает их: пишет в лог идентификатор и тип события, топик, партицию и offset.

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/events/health` | Проверка HTTP-сервиса: `{"status":true}` |
| `POST /api/events/movie` | Событие фильма → `movie-events` |
| `POST /api/events/user` | Событие пользователя → `user-events` |
| `POST /api/events/payment` | Событие платежа → `payment-events` |

Контракты запросов находятся в корневом `api-specification.yaml`. Успешный ответ `201` содержит `status`, реальные `partition` и `offset` подтверждённой Kafka записи и конверт `event`: UUID, тип, время создания и исходные поля события. Некорректный JSON, отсутствующие обязательные поля и неверные типы дают `400`; неподтверждённая публикация — `500`. Истечение таймаута ответа не доказывает отсутствие сообщения в Kafka, поэтому повторный HTTP-запрос может создать ещё одно событие.

Сервис не изменяет пользователей, фильмы, платежи или подписки: входящий `PaymentEvent` является тестовым событием, а не подтверждением оплаты.

## Конфигурация

| Переменная | По умолчанию |
| --- | --- |
| `PORT` | `8082` |
| `KAFKA_BROKERS` | `kafka:9092` |
| `KAFKA_GROUP_ID` | `cinemaabyss-events-service` |
| `KAFKA_PUBLISH_TIMEOUT` | `5s` |

При старте Kafka Admin создаёт три топика с одной партицией и одной репликой, если они ещё не существуют. Такая конфигурация рассчитана на учебный одноузловой кластер. Kafka должна быть доступна при запуске приложения; HTTP health отражает состояние самого приложения, а не постоянную доступность брокера.

Продюсер использует `acks=all` и идемпотентность Kafka producer. Обработчик фиксирует offset после успешного возврата из listener; повторная доставка при перезапуске допустима. Ошибка обработки повторяется два раза, затем записывается в error-лог. Это MVP обработки с логированием; сохранение бизнес-состояния и DLQ в его объём не входят.

## Сборка и запуск

```bash
# Из каталога сервиса, с JAVA_HOME, указывающим на JDK 21
mvn verify
KAFKA_BROKERS=localhost:9092 java -jar target/events-service.jar
```

Для локального запуска Kafka должна рекламировать адрес, доступный приложению. При запуске всего проекта через Compose используется адрес `kafka:9092` внутри Docker-сети.

Тесты проверяют HTTP-контракты и валидацию, обработку подтверждений/ошибок продюсера и публикацию с обработкой всех трёх типов в реальном embedded Kafka без Docker.
